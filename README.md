# חשבון חשמל – WattBill

מחשבון עלות חשמל ביתי בישראל, לפי כמות קוט״ש או לפי שתי קריאות מונה, כולל פענוח
הקריאה מתמונה של המונה. הכול רץ בדפדפן, בלי שרת ובלי הרשמה.

**האפליקציה:** https://taibavi.github.io/wattbill/

---

## מבנה הריפו

```
index.html                     האפליקציה כולה – קוד, עיצוב ולוגיקה בקובץ אחד
sw.js                          service worker: עבודה בלי אינטרנט והתקנה כאפליקציה
manifest.webmanifest           שם האפליקציה והאייקונים
icon-192.png / icon-512.png
data/tariffs.json              טבלת התעריפים. הקובץ היחיד שמתעדכן אוטומטית
scripts/fetch_tariffs.py       חילוץ התעריפים מספר לוחות התעריפים של רשות החשמל
.github/workflows/tariffs.yml  הבדיקה השבועית
```

`index.html` מכיל גם עותק מוטמע של טבלת התעריפים, שמשמש כגיבוי אם `data/tariffs.json`
לא נגיש. כך האפליקציה עובדת גם כקובץ בודד שנפתח מהדיסק.

---

## איך העדכון האוטומטי עובד

דפדפן אינו יכול למשוך קבצים מ‑gov.il: האתר לא מחזיר כותרת CORS, וכל בקשה מהאפליקציה
נחסמת. לכן הבדיקה לא רצה בדפדפן אלא ב‑GitHub Actions:

1. אחת לשבוע (יום שני, 04:17 UTC) רץ `scripts/fetch_tariffs.py`.
2. הוא מאתר את ספר לוחות התעריפים העדכני של רשות החשמל, מוריד אותו וממיר לטקסט.
3. מחלץ מלוח 5.3-1 את תעריף הצריכה והקיבולת לצרכן ביתי, ומלוח 5.4-1 את התשלום
   הקבוע לשירותי חלוקה ואספקה, למונה חד־פאזי ולמונה תלת־פאזי.
4. אם הכול עבר את בדיקות השפיות – `data/tariffs.json` מתעדכן ונדחף לענף הראשי,
   ו‑GitHub Pages מפרסם אותו מחדש.
5. האפליקציה מושכת את הקובץ בכל פתיחה ושומרת עותק מקומי. המשתמש לא מתבקש לאשר דבר.

### בדיקות השפיות

העיקרון: **עדיף ערך ישן ונכון מערך חדש ושגוי.** כל אחת מהבדיקות הבאות עוצרת את
העדכון לגמרי ומכשילה את ההרצה, כך ש‑GitHub שולח התראה במייל:

| הבדיקה | למה היא קיימת |
|---|---|
| התעריף הביתי חייב להיות זהה לתעריף הכללי | סדר העמודות בלוח 5.3-1 התהפך בין מהדורת 2024 למהדורת 07/2026. זו הבדיקה שתתפוס היפוך נוסף |
| סכום שלושת רכיבי השורה חייב להתאים לאחת מעמודות הסכום | בלוח 5.4-1 מיקום עמודת הסכום משתנה בין מהדורות |
| התעריף התלת־פאזי חייב להיות שונה מהחד־פאזי | מונע זיהוי של אותה שורה פעמיים |
| כל ערך בטווח סביר (למשל צריכה 0.30–1.20 ₪ לקוט״ש) | תופס פענוח שגוי של מספר |
| שינוי של יותר מ‑30% מול הערך הקיים | תופס מצב שבו נקראה מהדורה ישנה או לוח אחר |
| תאריך התחילה חייב להיות ה‑1 בחודש | בכותרת הלוח יש גם תאריך החלטה (למשל 8/12/2025). בלעדי הבדיקה הזו הוא היה נבחר, ואז עדכון אמיתי היה נדחה בשקט כ"ישן" |
| תאריך התחילה לא רחוק בעתיד | תופס פענוח שגוי של תאריך |
| ערך שהשתנה חייב תאריך תחילה מאוחר מהשורה הקיימת | עדיף לעצור מאשר לדלג בשקט על עדכון אמיתי |
| שתי שיטות פענוח שהצליחו חייבות להסכים | אם הן חלוקות, אי אפשר לדעת מי צודקת |

### ארבע שיטות הפענוח

כלי חילוץ טקסט שונים מפרקים את אותה טבלה עברית אחרת לגמרי, ולכן הסקריפט מריץ
ארבע שיטות בלתי תלויות על כל צורת טקסט, ומקבל את התוצאה רק אם כל השיטות
שהצליחו מסכימות ביניהן:

| שיטה | על מה היא נשענת |
|---|---|
| `שורות` | שורות טבלה שלמות, כפי שנוצרות ב‑`pdftotext -layout` |
| `רצף` | הטקסט כרצף אחד, כשכל תא יושב בשורה נפרדת |
| `חופשי` | קרבה בטקסט בין תיאור השורה למספרים, בלי הנחה על שורות |
| `מבנה` | שורות 9 ו‑10 (תשלום מראש) הן שכפול מדויק של 7 ו‑8, ולכן הן יוצרות רצף מתחלף. לא נקרא כאן שום טקסט תיאור – זו השיטה היחידה שעמדה בספר 07/2026, שבו שבר עמוד מפזר את תיאור שורת החד־פאזי בטבלת האספקה |

המע״מ אינו מסונכרן: הוא נקבע בחקיקה ולא מופיע בספר התעריפים, ולכן הוא מעודכן ידנית.

### הרצה ידנית

באתר GitHub: Actions ← "עדכון תעריפים" ← Run workflow. אפשר להזין שם כתובת PDF
מפורשת אם איתור הספר האוטומטי נכשל.

מקומית:

```bash
python3 scripts/fetch_tariffs.py --data data/tariffs.json --dry-run
python3 scripts/fetch_tariffs.py --text book.txt --dry-run --data data/tariffs.json
```

`--dry-run` מדפיס מה היה משתנה ולא כותב כלום.

ומול פרסום רשות המסים לשיעור המע״מ. **הנתונים תקפים מ‑1 בינואר 2023 ואילך.**
רשימת המקורות המלאה, עם קישור לכל שורה, נמצאת בתוך האפליקציה – במסך "אודות"
ובטבלת רכיבי העלות.
